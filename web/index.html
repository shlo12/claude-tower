IPv6 出口（Wi-Fi）
检查中

          
代理通常只接管 IPv4。这台机器如果有全局 IPv6 地址和 v6 默认路由，客户端可能绕过代理、从真实 ISP 直连。原检测文章建议在系统层把 IPv6 配置为「关闭」，而不是只关代理。

          
关闭范围只限 Wi-Fi 网络服务，以太网、VPN、USB 网络等其它服务不动。只改系统 IPv6 配置，不改代理软件里的 ipv6 开关，也不验证代理远端解析；关闭后 IPv6-only 热点会断，依赖 v6 的应用可能受限。随时可恢复为 Automatic。

01因果不可观测，所以没有人能向你保证最重要的一条

        
账号处置是大模型公司的单方面决定，绝大多数时候不会给出具体理由。这意味着没有任何人（包括本工具）能证明某一项操作有效或无效——既无法验证，也无法反证。以下三种情况都真实存在，而且从外部无法区分因果：

        
    
          
  • 有人什么都没改，用了很久也没事；
    • 
          
  • 有人严格照着清单逐条改，仍然被封；
    • 
          
  • 有人改完第二天就封了——可能只是时间上碰巧。
    • 
        

        
所以：任何声称「照做就安全」「按这套流程就不会封」的说法，都不成立。本程序也不会这么说。

      


      

        
02这不是「防封工具」，而且它会真的改你的机器

        
本程序分两半：前半段只读——读取这台机器上已有的配置与文件，对照一份由公开资料整理出来的清单打分；后半段会写——在你确认之后，它真的会去改那些文件。

        
它会执行的操作只有下面这几类，没有别的：

        
    
          
  • 改写或删除配置字段；含密钥或令牌的文件不保留副本
    • 
          
  • 缓存、诊断日志、凭据及含令牌的客户端存储直接删除，不进废纸篓，无法还原；其他文件按预览处理
    • 
          
  • 真正移除 Shell 中选中的密钥赋值行；非敏感配置行按需注释
    • 
          
  • 重新生成 ~/.claude.json 里的机器标识，让它不再对应本机
    • 
          
  • 删除钥匙串里与服务相关的条目——这一项没有备份，删了就是删了
    • 
          
  • 设置或清除环境变量、移除登录启动项
    • 
          
  • 修改系统时区（会弹系统授权框，密码得你自己输）
    • 
          
  • 关闭或恢复 Wi-Fi 网络服务的 IPv6 配置（会弹系统授权框，记录原状态后可恢复为 Automatic；其它网络服务不动）
    • 
          
  • 写入或撤销 FlClash / Clash Verge / ClashX 的分流附加规则（只在「隐私设置」里，执行前必须预览确认；会退出并重开对应客户端，撤销只删本工具记录的行；其它客户端只给手动步骤）
    • 
          
  • 结束正在运行的 Claude 相关进程
    • 
        

        
清理前会给你预览清单，并要求输入 CLEAN。不留副本的项目会明确标出，不可还原。其他配置按清单保存非敏感副本。还原旧文件时也会检查，拒绝重新引入已识别的缓存、日志或凭据。安全快照不包含这些内容；历史旧备份不会自动删除。

        
它不修改 Anthropic 的任何设置，不接触你的账号，不代理、不转发你的任何请求，也无法影响服务端的任何判定。所有改动都只发生在你这一侧的机器上。

        
本程序与 Anthropic 没有任何关联，不是官方产品，也未获其认可或授权。「Claude」等名称仅用于说明检测对象。

      


      

        
03结论只说明「信号密度」，不说明「安全」

        
清单里每一条建议的本质，都是少留下一个可被观察到的特征。改时区、换主机名、删中文输入源、固定出口、关掉 WebRTC——这些动作做与不做，是在减少或增加「被观测到的信息量」，而不是在产生任何形式的「安全」。

        
这两件事必须分开：信号少 ≠ 不会被封，信号多 ≠ 一定被封。把它们当成一回事，是这类清单最容易被误读的地方。

      


      

        
04不要为了「看起来一致」去改真实资料

        
如果你的时区、语言、输入法、Apple ID 地区、付款方式本来就对应你的真实身份，那就让它们保持真实。为了让几个字段互相自洽而去伪造或扭曲真实信息，往往会制造更多不一致——账单地址与支付方式对不上、设备资料与实际使用地长期冲突、注册信息与历史记录矛盾。这类矛盾比「时区是台北」要严重得多。

        
清单里与你实际需求冲突的条目（工作语言必须是中文、家人共用这台电脑、公司统一发的设备、必须用的中文输入法），请直接忽略。真实需求优先于表面一致。

      


      

        
05本工具不提供、也不鼓励任何规避手段

        
本程序不提供账号共享、代充代付、伪造身份、绕过地区限制、批量注册、自动化刷量等任何做法，也不对这类行为给出建议。清单里的每一条都只是「减少本机可观测特征」，没有一条是「绕过某项限制」。

        
清理会改动你本机的真实配置。如果某项配置对应你的真实工作环境——公司统一发的设备、家人共用的电脑、团队约定的语言、必须装的中文输入法——改动它可能影响正常使用。只勾选你理解后果的条目。

        
请自行确认你的使用方式符合 Anthropic 的服务条款与你所在地的法律法规。因使用本程序或采纳其中任何建议而产生的直接或间接后果，由使用者自行承担。

      


      

        
06数据：读了什么，去了哪里

        
    
          
  • 主要在本机执行和记录。本工具不会自动把本地扫描记录上传到项目服务器；部分诊断需要访问第三方服务。
    • 
          
  • 会联网的检测：出口信息与风险查询、DNS / DoH、STUN、固定 HTTPS 连通性诊断及版本查询等，会访问相应第三方服务；配置自动更新后还会访问所选 GitHub 仓库。对方能够看到请求来源的出口 IP，部分查询会发送待检查的 IP 或域名。“本地运行”不等于完全离线。
    • 
          
  • 出口历史落在本机：「出口漂移」这一关需要历史才能判断，因此每次检查会把当时的出口 IP、国家、城市、ASN 记到 ~/.ccclean/egress.json（最多保留 60 条）。这个文件只在本机，删掉它漂移记录就清零。
    • 
          
  • 凭据与本地文件：不会把凭据作为诊断请求发送。部分扫描和清理会在本机读取配置原文，以识别密钥并过滤敏感内容；本地记录和备份仍应视为私有资料，不要公开整个 ~/.ccclean 目录。
    • 
        

      


      

        
07分级与分数只是表达方式

        
critical / high / medium / low / pass 这五档、通关进度、装备、勇士等级，都是把检查结果游戏化的表达。它们不是风险概率，也不是大模型公司的任何真实阈值——这些阈值由本工具自行设定，属于经验判断，没有官方依据。请把它们当作「优先级排序」，而不是「出事概率」。

        
同理，打通全塔不代表你安全，卡在某一层也不代表你危险。
