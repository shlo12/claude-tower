# 虚拟机固定代理与断网保护

此功能仅用于专用的 macOS 客机。普通电脑构建不启用；安装器会检查
`kern.hv_vmm_present`，不能把它当作宿主机网络设置工具使用。

## 使用现有网络，不安装第二个代理客户端

客机继续使用 `/usr/local/etc/mihomo/config.yaml`、已有 TUN 和
`com.vmproxy` pf anchor。系统代理可以关闭；mihomo 使用规则模式。
实际规则须拒绝公网 UDP，并以 `MATCH,PROXY` 结束。DIRECT 只允许私网
和回环例外；不接受其它公网直连分流或第二个代理策略。

`PROXY` 的实际选择链必须明确，每一级只能包含一个批准成员。存在其它
备用成员时，安装器会拒绝，不会静默把它们当成安全配置，也不会替用户选择
另一个节点。安装器不改 mihomo 凭据、节点或 DNS；先核对现有配置再安装。

## 整机断网保护

pf 只允许指定 TUN、回环、指定物理网卡到批准代理 IPv4 与固定端口的 TCP，以及
到广播地址/当前私网 DHCP 服务器的租约通信。其余所有接口、地址族、协议
的出站默认拒绝，包括新增网卡和物理 IPv6。不是依靠结束 Claude 来阻断网络。

安装时将原始 pf 文件备份到 root 私有目录；不复制 mihomo 配置或密钥。
持久化的 pf anchor 默认封闭出口。root 任务每 10 秒核验实际内核运行模式、
规则、单成员节点链、配置指纹和指定 TUN 路由，通过后只开放批准端点。
证据不满足时封闭物理出口并清理既有状态；后续只会恢复同一份批准策略。
代理端点不可达时没有其它网络备用路径。关闭 Tower/Shield 不会卸载 pf 或任务。

此处的“所有网络”不包含必要的本机回环和 DHCP。HTTP 出口经 SS 首跳到达时，物理白名单只填 SS 首跳，不能额外放行 HTTP 出口。
批准的代理端点是显式白名单，
不会根据探测结果自动增加。定时检查存在采样间隔；具备客机 root 权限的软件仍可
更改系统策略。安装及运行检查不能替代开机最早期抓包、切网和代理故障的实机验收。

## Tower 与 Shield 共用证据

root 任务输出 `/var/run/ccclean-vm-network.json`。文件不含 API 密钥或节点名；
应用只接受 root 所有、其他用户不可写且 25 秒内的新鲜状态。过期、缺失或失败
都拒绝戒严准入。没有 STUN 回包只有在运行中 UDP 拒绝规则与 pf 同时核验后，
才显示“已阻断”；单纯超时仍不算通过。实际收到 UDP 回包则拒绝准入。DNS 查询与 fake-ip 接管必须明确成功；解析器国家归属
是附加元数据，查询不可用不等于路径泄漏，也不会替它编造一个国家。

虚拟机版不提供普通客户端的分流/DNS 改写、Wi-Fi IPv6 修改、终端代理代写或
FlClash 接口创建，以免改坏固定链路。时区、语言、缓存清理等仍在客机内部使用。
虚拟机和虚拟显卡信息保留为说明，不因用户主动使用虚拟化而要求“修复”。

## 安装与验收

应用包 `Contents/Resources/vm-network-tools/` 附带安装器与保护脚本。
安装器默认只预览；经审核确认的管理员操作才使用 `--apply`。在客机执行：

```sh
sudo /usr/bin/python3 -I install-vm-network.py \
  --interface <客机物理接口> --tun <实际TUN接口> \
  --allow-ip <批准的首跳代理IPv4> --port <该代理TCP端口>
```

加入 `--apply` 才写入和加载，现有连接会被重建。参数必须来自实机核对，
示例不是可直接复制的部署命令。预览失败时先定位配置问题，不应关闭保护绕过检查。

部署后必须验证：正常访问只使用批准链路；停止 mihomo 时公网 TCP、UDP、IPv6
与强制物理接口访问均失败；恢复同一内核后恢复原链路；新网卡、模式/节点变化
与重启不会提供另一出口。维护通道应使用既有虚拟化工具，不重新开放宿主文件服务。

源码的隔离回归和 pf 语法检查已覆盖默认拒绝、故障封闭、清状态、过期/伪造证明、
TUN 规则模式准入和普通网络修复禁用。实机部署、故障演练结果需另行记录，
不能把测试通过写成已经在用户虚拟机生效。

## 2.23.1 / Shield 1.13.1：不稳定网络的恢复期

启动前仍需完整检查通过。已准入后，只有 root 固定链路保护新鲜且有效、节点与实际出口没有确认变化时，暂时查不到 DNS、HTTPS 传输或边缘出口会进入最长 120 秒恢复期。面板显示黄色警告，保留原会话并自动重新查询；恢复即解除警告，连续超时才结束 Claude。

pf、指定 TUN、节点身份、实际出口变化、TLS 证书异常、已确认 DNS 接管失效或收到违反拒绝策略的 UDP 回包，仍立即处理。此恢复期不会放宽 pf 放行规则，也不会添加备用出口。关闭 Shield 后，root 网络保护仍独立运行。普通电脑版本维持原判据。

## 宿主傳檔

使用獨立的「傳入虛擬機」宿主小工具，可在保持共享資料夾、剪貼簿與拖放關閉的狀態下，將指定檔案傳入客機。收件與取消行為見同目錄 `VM_TRANSFER.md`；此工具不更改固定鏈路或 pf 規則。

## 2.23.2 / Shield 1.13.2：修复 HOME 启动环境

部分启动链会继承 `HOME=/`。Claude 的本地会话因此可能把信任配置写到只读根目录 `/.claude.json`，出现无法保存信任或建立工作区的错误；这不是证书信任设置错误。

Tower、Shield 和看门狗现在会在入口修复空白、根目录或不可用的 HOME；从系统用户资料取得真实目录作为回退，并显式传给子程序。合法、可写的隔离 HOME 与 CFFIXED_USER_HOME 保留，自定义 CLAUDE_CONFIG_DIR 不被删除。无法取得可写 HOME 时，不启动 Claude。

此修复不重设钥匙圈、不更改根目录权限、不重建用户配置，也不修改网络及 pf。旧进程必须退出后重新启动，新的启动环境才会生效。
